# r-doc 三项真实任务试点与路线建议

状态：本轮候选二开、三个真实任务评测、适用回归和独立审查已完成。当前候选未达到正式采用条件；评测完成不等于三个任务均运行通过。

## 建议

建议下一阶段继续维护小范围 fork，优先把项目元数据适配和流程收敛做成可配置扩展；保留转向逐步自建的选项，暂不作长期完整 fork 或全面自建的承诺。当前候选冻结为试验基线，不安装为团队默认、不作为正式审计门禁。

依据是：现有项目元数据和批准语义需要真正适配；跨仓版本与知识失效需要额外契约；本轮未证明完整 r-doc 流程比无技能组更可靠或更省事。但当前补丁仅 7 文件，自建也没有对照实现或成本证据，不能从“r-doc 尚未证明增益”直接推出“自建更划算”。小 fork 是下一步可逆的试验载体，其是否值得长期保留仍需新任务结果。

转向逐步自建的触发条件应明确：在约定的一轮最小元数据扩展及收敛改动后，仍须长期绕过大部分上游流程、改变其核心生命周期，或相同预算下仍无收益，则提取有用的通用模块，逐步替换项目工作流。现阶段没有证据支持从零重写整套文档系统。

三个任务来自同一个真实 OTA 历史变更的不同工作场景，属于隔离历史回放，不是三个独立业务发布。产品来源为 `a6b28035c577131c1a4b0262af6ddbdc393104c5` → `e38d162feba9445c3bedb6ec78d96ee79dee9a49`；文档来源为 `b16030c10cf2565ecfa16ab19ee43a3a273bec57`。父仓结构是用真实文件构造的样板，实际仓库没有整体迁移。

任务一旧批次的判据缺少 shebang，任务三旧判据未正确接受历史版本引用，均保留原始 FAIL，修复后另记评分。任务三首轮还出现启动器缺失；恢复组串行且禁止嵌套 Agent。恢复组两次超时保持 ERROR，不用报告已写出替代正常结束。

主要旧批次 16 次运行已按准确会话 ID 回查实际模型，均为 `gpt-6-astra / ultra`；历史报告里的“型号尚未解析”是当时状态。用户随后要求优先 `gpt-6-astra / xhigh`，新独立审查采用该组合。不同并发度、宿主配置、提示已明确约束及单次样本，限制了效率和因果结论。

## 候选身份与维护成本

固定上游为 `bc23420d7df5ec1d2c5fb45e066c919790ab9cf9`。最终候选为 `rdoc-pilot-maintenance-v3`，`SKILL.md` SHA-256 为 `05710de6c26c3c51883753db7f58e1da34c51644e8e5ab1392fb2086b984f5ba`；完整 59 个源码文件的指纹见候选清单。

相对上游共改 7 个文件，增加 145 行、删除 23 行，其中新增回归测试 90 行。主要修改是保留带空格的尖括号 Markdown 目标、从根 AGENTS 计算文档可达性、增加跨仓发现和有界维护入口。完整候选已有 144 项单元回归通过；最终核对 59 个文件与该回归工作区一致。发现路径在最终 v3 重新执行，未借用 v2 的通过。

真实文档样板用项目已有元数据校验器检查通过，r-doc 全库审计却输出 241 项基线问题，其中包括 110 项字段和 22 项状态差异。r-doc 固定的字段、类型和生命周期无法仅靠现有配置映射到项目的 `document_kind`、`approved`、`pass`。这些审计结果不等于 241 处业务错误；也不能通过删除批准状态或排除全部文档来伪造兼容。

| 路线 | 结论 | 条件和成本 |
|---|---|---|
| 固定上游加配置 | 可做辅助工具，不足以成为项目统一知识门禁 | 现有配置缺少项目元数据映射和跨仓语义核验 |
| 小 fork 上继续有界适配 | 推荐作为下一阶段试验载体；不是正式采用 | 当前补丁小；先验证 schema 扩展和执行收敛能否解决主要缺口 |
| 长期维护完整 fork | 暂不承诺 | 仍需承担版本语义、执行预算和上游更新，缺少稳定收益证据 |
| 逐步自建薄适配层并选择性复用 | 保留为有明确触发条件的备选 | 自建收益和成本未验证；上游核心模型持续成为负担时再逐步替换 |

## 独立审查与缺口处置

独立审查使用 `gpt-6-astra / xhigh`，实际会话型号已核验。第一次审查因只读沙箱无法访问材料而未完成，原报告保留。恢复审查使用同字节、哈希核对后的可读隔离副本，253.964 秒正常结束，副本未变；审查核对 59 个源码文件与 16 项具名证据。它是独立上下文的模型审查，不是人类批准或产品发布验收。

审查确认一项 P2 上游遗留缺陷：`scripts/rdoc/markdown.py:152` 要求 `>` 后紧接 `)`，对 `[x](<missing.md> "title")` 返回空目标列表，造成坏链接漏检，或存在的唯一入口被误报不可达。协调方用内存最小片段在上游和 v3 均复现，见复现记录。该缺陷未修复，列为**采用审计门禁前必须修复**；本轮冻结候选并不采用，不能把 144 项回归通过说成没有缺陷。

独立审查未确认本次差异引入其它新缺陷，但认为证据不足以作长期路线承诺，并建议保留小补丁试点，先考虑通用修复与元数据配置扩展。最终建议采纳了这一收窄：原草案的“优先逐步自建”缺少自建对照，不作为正式结论。正文唯一、历史保留和四种发现条件已有证据；任务三超时、全库 schema 不兼容、流程额外开销、网关/前端未覆盖均作为剩余缺口，不改判通过。

## 父仓的最小实现边界

父仓拥有项目文档、业务知识导航和版本组合。`ming-iot`、`mqtt-gateway` 与前端继续保留独立 Git 历史，通过固定子仓 revision 协同。项目专用 ai-native 内容进入父仓，跨项目复用工具保留单独来源，以固定版本接入。

根文件建议命名为 `AGENTS.md`，包含用户要求的四部分：仓库地图、快速命令、关键约定速查、当前状态表。正文保持短小；地图链接到拥有事实的文档，命令链接实际脚本，状态引用验收证据，避免再建一份竞争的业务事实副本。

跨仓证据至少具有 `repo/path/revision`，选择性复制再补内容哈希和来源清单。区分规格约定、当前实现、历史基线和实际验证结果。子仓缺失返回未知，旧 revision 不自动等同正文失效。OpenSpec 仍是待定方案。

先定义“发现、定点更新、失效核验”三个有界入口，分别明确输入、允许写入的正文所有者、输出和结束条件。六个目录可以先作为知识分类；只有触发与写入契约确实不同才拆成六个 Skill。

| 目录 | 首先建立的约定 | 本轮覆盖限制 |
|---|---|---|
| `docs/specs/` | 业务正文所有者；批准与实现验证分开 | 仅一个 OTA 主题 |
| `docs/changelog/` | 已做与待做区分，引用变更和证据 | 未验证完整时间线维护 |
| `docs/architecture/` | 连接两端、接口、所属仓及版本 | 仅相关接口字段和跨仓版本 |
| `docs/runbook/` | 环境、前提、实测步骤和失效条件 | 未验证操作与恢复 |
| `docs/vendor/` | 选择性来源清单、revision、哈希与影响核验 | 仅真实 OpenAPI 快照；不是完整同步工具 |
| `docs/wiki/` | 人工维护边界，AI建议与正式规范分开 | 未验证人工协作机制 |

## 下一阶段的验收建议

1. 在新候选中修复已复现的 P2，增加带标题链接组合回归；修改后重做受影响证据。当前 v3 的评测记录保持原样。
2. 在小 fork 上先尝试项目元数据扩展和明确结束条件，优先复用项目校验器。选择一个新的真实小任务，与无技能基线在相同 `gpt-6-astra / xhigh`、预算、并发和验收条件下对照；不要给旧失败例单独加时。
3. 正确产物和按预算正常结束同时满足才计运行通过。若流程只增加审计与上下文而没有可观察收益，应删减或停止该路径。
4. 选择性复用前保留 r-doc 来源、许可证与补丁记录；正式 fork 发布、全局安装和整体 GitHub 迁移作为后续单独交付。
