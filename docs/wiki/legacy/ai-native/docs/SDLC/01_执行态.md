# 执行态
一个任务从开始到结束不是只有生成，还需要理解问题做取舍检查结果，以及确认这些改动有没有带来新的问题。
AI Coding产出的速度明显快过人理解和确认这些产出的速度。
人工Coding虽然慢，但在实现的过程中也在逐步理解这个系统，为什么这里要加一个字段那里加一个状态，哪些由历史包袱，在动手的过程中是慢慢想清楚的，现在AI可以帮助程序员直接跳过实现步骤，却不会自动把这些理解一起交给程序员，程序员拿到了结果但却没有建立起足够的认知。这也是为什么AI已经把东西做出来了，程序员却越来越不敢让它继续改，也越来越无法对它提出的问题做出决策。
有人会说，不要管实现具体的实现了，只负责目标、判断和验收，这句话听起来很合理，但是并没有真正解决问题，因为目标、判断和取舍本身就是工作里最难的部分，以前难现在也难，AI只是让这些事情变得更重要了而且更高频，但并没有保证他们变得更简单，如果最后的解法只是人要更会提需求更会做判断，那相当于把最难的工作集中起来了又重新返还给了人，所以现在最重要的不是怎么让Agent一次多做一点而是让它用一种人类更容易理解更容易判断的方式把工作交回来。
1.缩小每次需要人工验证的范围，不是机械地要求它少写几行代码也不是每一步都停下里问人类，而是一次先交付一个能够独立确认地结果：
比如：修改项目完成度
	定义完成 -> 状态规则 -> 例子验证
让本轮地边界、结果和未确认项，都能说清楚。

人类底线：
每一轮结束，我能不能说清楚它改了什么，为什么这么改，凭什么认为它是对的，这三件事情弄清楚再进行下一轮
