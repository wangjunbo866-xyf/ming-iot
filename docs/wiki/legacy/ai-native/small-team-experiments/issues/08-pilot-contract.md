## Question

由用户选择一条真实 IoT 需求，形成短周期试点计划：范围、参与者、至少一次交接、独立复现步骤、关键验收、基线和观察指标、结束及暂停条件。区分需求完成与团队机制有效，不以代码生成量或 Agent 活跃时长代替交付收益；先确认最优先解决的协作问题，再选择指标。

## Context

用户已选现有 IoT 需求交付；候选需求、首要问题与具体团队配置仍等待用户答复。本票据交付试点计划，不执行业务需求。
