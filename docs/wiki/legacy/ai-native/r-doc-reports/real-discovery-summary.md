# r-doc 真实 OTA 检索试验与第二版候选

日期：2026-10-12。阶段：跨仓上下文发现的部分文件切片验证。

结论：新增的只读发现路径通过三种材料条件，且实际轨迹均未执行全库审计。可以把第二版作为后续试验起点；目前没有足够证据证明它整体优于原版或无技能，也不能据此选择长期 fork 或自建。

## 输入与处理

- 冻结输入：[首轮清单](../real-cases/ota-module-code/manifest.json)、[评测清单](../real-eval-v1/frozen-suite-manifest.json)。使用实际 OTA 历史的代码、正式 Spec、Plan、Review 和 Evidence；新增来源清单只解释版本与切片范围，不提供答案。
- 三种条件：双仓材料齐全、缺少产品代码仓、单独打开产品代码。它们都是明确标注的部分文件切片，**不是完整 Git 仓库检出**。
- 第一批分别运行无 r-doc、固定原版、首轮候选，共 9 次。第二批只修改候选 `SKILL.md` 的任务分流，复用相同输入、提示、judge、240 秒预算和默认引擎，再运行 3 次。
- 已补入首轮裁剪遗漏的两份直接链接目标；审计数量不作为业务正确性判据。完整判据包括字段与类型、权威 Spec、版本绑定、缺失材料、原文引用、未冒充本次产品测试以及既有材料保持不变。
- 本批实际 CLI 版本均为 `0.154.0`；未覆盖模型、provider 或 base_url，沿用宿主设置。运行报告未给出解析后的模型名，因此不声称已经固定并核验模型版本。全局技能及配置也未隔离。

## 结果

单元格为运行结果 / 耗时秒 / 已完成 shell 命令数。ERROR 均为 240 秒超时。

| 条件 | 无 r-doc | 原版 | 首轮候选 | 第二版候选 |
| --- | --- | --- | --- | --- |
| 双仓材料齐全 | ERROR / 239.9 / 9 | PASS / 227.8 / 13 | ERROR / 239.9 / 21 | PASS / 235.9 / 19 |
| 缺少产品代码 | PASS / 225.7 / 8 | PASS / 221.0 / 10 | ERROR / 239.9 / 11 | PASS / 213.4 / 15 |
| 单独产品代码 | PASS / 124.4 / 5 | PASS / 175.5 / 17 | PASS / 161.6 / 17 | PASS / 159.6 / 15 |

- 12 次运行中，9 次正常通过、3 次 ERROR。超时前产出的三份报告，其关键字段和原文引用复核也正确；这只是部分产物证据，**不升级为运行 PASS**。
- 原版及首轮候选的三种条件各执行一次全库审计。第二版的三种条件均为零次；三份报告仍能区分正式业务依据、实际代码、历史 Evidence、实施授权缺口与未提供的仓库。
- 第二版三次运行的完整来源不变性 judge 均通过；所有已采集来源文件的哈希也未发现变化。原产品仓保持 clean，文档仓既有未跟踪 Proposal 保留。
- 初轮日志有模型目录、插件目录、WebSocket 网络告警与重连；部分运行在超时前已生成报告。不能把这些 ERROR 单独归因于技能语义，也不能把第二版通过全部归因于本次修改。
- 单次样本、并行重叠、执行顺序及网络状态都会影响耗时。第二版命令数没有一致下降，耗时也没有一致优于原版或无技能；当前只确认任务分流行为发生了预期变化。

## 本次二开

第二版位于 [real-eval-v2-discovery/r-doc](../real-eval-v2-discovery/r-doc/SKILL.md)，差异和指纹见 [change-manifest.json](../real-eval-v2-discovery/change-manifest.json) 与 [discovery-mode.patch](../real-eval-v2-discovery/discovery-mode.patch)。

只读问题以必要来源、版本、实际实现、历史验证和缺失说明为完成条件；文档修改、同步和显式审计继续走原有治理流程。仅 `SKILL.md` 改动，脚本、题目和 judge 未改。技能格式检查与三项真实 Agent 复测通过；没有用匹配提示词文本的测试代替行为验证。

首轮候选和输入证据保留不变。第二版尚未安装为全局默认，也未发布。

## 下一步与未覆盖

1. P0 仍保持 open：补齐真正完整检出的父仓/子仓拓扑与版本组合验证；本轮切片三条件不能替代该要求。优先复用现有结果，扩展新增维度，不无理由重跑相同输入。
2. 以第二版为后续试验起点，执行唯一权威文档更新。已有 `document_kind`、`approved/pass` 与 r-doc 默认模型不兼容仍未修复；只读模式减少审计并未解决该问题。
3. 执行真实代码前后版本的知识失效检测，区分现行陈旧内容与明确标注的历史依据。
4. 最终候选仍需适用回归、独立审查和维护成本评估。三个真实任务的整体验收与 fork/自建路线决定均未完成。
