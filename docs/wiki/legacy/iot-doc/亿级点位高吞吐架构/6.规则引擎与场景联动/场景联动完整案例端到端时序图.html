全链路总览

Canonical → Current Fact → Scene → Command，最终由 Reducer 提交 AcceptedStateTransition。

阶段 1：设备上报与 Durable Canonical

本阶段成功意味着

RawRecord 已可靠接收，Canonical PropertyReport 与 nextOffset 已在同一 Kafka 事务中持久化。

本阶段成功不意味着

不代表 Current Fact 已投影、Scene 已求值，也不代表任何设备动作已经接受或完成。

阶段 2：共享计算、投影与 Admission

本阶段成功意味着

各消费者组可以独立完成时序物化、共享指标计算、Current Fact 投影或 Scene Admission。

本阶段成功不意味着

某一个 consumer group 完成，不代表其他组已经完成，更不构成跨组读取屏障。

阶段 3：Scene 求值与持续复核

本阶段成功意味着

Scene 在一致的读屏障下获得 READY 事实，并在持续时间到期时重新验证上下文、身份和谓词。

本阶段成功不意味着

timer expiry 只表示到了复核时刻，不证明条件仍为 true，也不会绕过 missing 或 freshness 策略。

阶段 4：动作接受与投递

本阶段成功意味着

PostgreSQL commit 已原子记录整组动作及 acceptedAt，后续投递可按 effectId 幂等恢复。

本阶段成功不意味着

PG commit 仅表示 action accepted，不表示 fan-01、fan-02 已执行，也不表示 Webhook 已完成。

阶段 5：回复归并与状态联动

本阶段成功意味着

Reducer 已持久化回复观察；只有合法单调状态变化会产生 AcceptedStateTransition，并由感兴趣的 Binding 重新进入 Scene。

本阶段成功不意味着

CommandReply 等 observations 不能直接触发 Scene；只有 reducer 接受的 state change 才可以触发。
