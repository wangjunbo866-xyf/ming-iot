# Typed Payload Pool Implementation Plan
## Context
设备高频 Modbus 数据解码路径中，每个点位产生 `map[string]any` + `decimal.Decimal` + `cast` 转换，百万设备每秒上报时造成 GC CPU 飙升和内存碎片。设计文档提出 `PointValueRef + Ints/Floats/Text arena` 替代方案，按设备型号池化复用。

本次实现覆盖阶段 1~4：Schema Runtime Index → Payload Types + Pool → Typed Decode + Verifier → 接入主流程。SQL Builder 池和 Event Lookup Cache 不在本次范围。

### 1.3 新建 `schema/runtime_index.go`
```go
type SchemaRuntimeIndex struct {
    PropertyDict *PropertyDict
    EventLookup  map[EventLookupKey]EventLookupMeta
}
```

实现 `BuildRuntimeIndexes()` 方法：

1. 遍历 `Model.Properties`，对每个属性解析 `ExtendConfig` JSON 得到 `base-addr/scaler/vdata_type`
2. 结合 `Route[identifier]` 得到 `ModuleID/ModuleCode`
3. 根据 `Define.Type` 推导 `ValueKind`，根据 `vdata_type` 字符串推导 `PropertyDecodeKind`
4. 解析 `min/max/step` 为 typed 字段（int64 或 float64）
5. 解析 enum mapping 为排序后的 `[]int64`
6. 按 `(ModuleID, Identifier)` 排序后分配 `PointID uint16`
7. 去重 module 构建 `Modules []ModuleMeta`
8. 遍历 `Model.Events`，解析 `ExtendConfig` 中的 `alarm_code`，构建 `EventLookupKey -> EventLookupMeta` map

关键映射逻辑（来自设计文档 3.1.1 适配表）：

+ `vdata_type` U16/S16/U32/S32 + `Define.Type` float/double → `ValueFloat`
+ `vdata_type` U16/S16/U32/S32 + 其余数值类型 → `ValueInt`
+ `vdata_type` 20 Byte/22 Byte + `Define.Type` string → `ValueString`
+ `vdata_type` U32 + name 含"版本" → `DecodeU32Version` → `ValueString`
+ `vdata_type` 40 Byte/38 Byte/8 Byte → `DecodeSkip*`，不生成 descriptor
+ `vdata_type` 6 Byte → `DecodeBCDTime6` → `ValueString`

## Phase 2: Payload Types + Pool
### 2.1 新建 `payload/types.go`
```go
type PointValueRef struct {
    PointID uint16
    Kind    ValueKind
    Index   uint32
}

type StringRef struct {
    Off uint32
    Len uint32
}

type ModbusBlock struct {
    ID      int32
    Offset  int32
    DataOff uint32
    DataLen uint32
}

type ModulePayload struct {
    ModuleID  int64
    Timestamp int64
    Values  []PointValueRef
    Ints    []int64
    Floats  []float64
    Strings []StringRef
    Text    []byte
}
// 方法：AddInt, AddFloat, AddString, AddBytes, Reset, HasValues

type ModulePayloadBatch struct {
    ProductID     string
    DeviceName    string
    SchemaRelease int64
    Timestamp     int64
    Modules      []ModulePayload
    Blocks       []ModbusBlock
    BlockScratch []byte
}
// 方法：Reset
```

### 2.2 新建 `payload/pool.go`
```go
type ModelPayloadPool struct {
    key            PayloadPoolKey
    moduleCount    int
    maxPoints      int
    maxTextBytes   int
    maxBlocks      int
    maxBlockBytes  int
    pool           sync.Pool
    inFlight       atomic.Int64
    lastBorrow     atomic.Int64
    lastReturn     atomic.Int64
    retiredAt      atomic.Int64
}

type PayloadPoolManager struct {
    mu    sync.RWMutex
    pools map[PayloadPoolKey]*ModelPayloadPool
}
```

实现：

+ `NewModelPayloadPool` — `sync.Pool{New: func() any { ... }}`，按 dict 容量预分配
+ `PayloadPoolManager.Borrow(dict *schema.PropertyDict) (*ModulePayloadBatch, *ModelPayloadPool)` — 锁内查/建 pool + 递增 inFlight
+ `ModelPayloadPool.Put(batch *ModulePayloadBatch)` — 容量保护 + 递减 inFlight
+ `PayloadPoolManager.RetireProductOldReleases` — 标记旧 release pool 为 retired
+ `PayloadPoolManager.Sweep` — 定期清理 retired + inFlight==0 的 pool

+ `payload/pool_test.go`：验证 Borrow/Put 配对、超限丢弃、inFlight 计数

## Phase 3: Typed Decode + Typed Verifier
### 3.1 新建 `binaryTransform/decode_typed.go`
`buildModbusBlocks`：遍历 `deviceMsgInverter["DATA"]` 一次，hex decode 每个 VALUE 到 `BlockScratch`，生成 `[]ModbusBlock` descriptor。

`findBlock`：线性查找（当前 DATA 块数量通常 < 8）。

`appendHexStringDecoded`：直接按 string 下标解码，零临时分配。

`DecodePropertiesIntoPayload`：

1. 调用 `buildModbusBlocks`
2. 遍历 `dict.Points`（不是 `tslProperties`）
3. 对每个 plan 调用 `findBlock` + `decodeOneProperty`
4. `defer` 清零 `Blocks` 和 `BlockScratch`

`decodeOneProperty`：按 `plan.DecodeKind` 分支，调用 typed verifier 直接写入 `ModulePayload`。

辅助函数：`readU16`, `readS16`, `readU32`, `readS32`, `readBytes`, `trimZeroSpaceBytes`, `decodeVersionBytes`。

### 3.2 新建 `binaryTransform/typed_verifier.go`
+ `scaleFloat(raw int64, scaler int8) float64` — 查找表，替代 `decimal.Decimal`
+ `scaleInt(raw int64, scaler int8) int64`
+ `appendVerifiedInt(plan, raw, payload)` — clamp min/max + step + enum check
+ `appendVerifiedFloat(plan, raw, payload)` — clamp min/max + step
+ `appendVerifiedBytes(plan, value, payload)` — MaxStringLen 截断
+ `appendVerifiedIntOrFloat(plan, raw, payload)` — 按 ValueKind 分派
+ `stepFloatTyped(val, step float64)` — 复用 `thingmodel.stepFloat` 语义

### 3.3 测试
+ `binaryTransform/decode_typed_test.go`：
    - 构造 PropertyDict + 模拟 deviceMsgInverter
    - 验证各 DecodeKind 正确写入 typed arena
    - 对比测试：同一输入，旧 `DecodeProperties + VerifyProperties + SplitByModule` 输出的 map 与新链路输出的 typed payload 恢复后的 map 逐字段比较

## Phase 4: Integration
### 4.1 修改 `ps_lookup.go`
在 `Lookup` 方法中，为每个子设备的 `oneSchema` 新增 `propertyDict` 字段：

```go
if bundle != nil {
    if dict := bundle.GetPropertyDict(); dict != nil {
        oneSchema["propertyDict"] = dict
    }
}
```

### 4.2 修改 `handle_push_data.go`
新增全局 `payloadPoolManager`（包级别变量，在 `init` 或首次使用时初始化）。

属性路径改为：

```go
dict, _ := oneSubsetMap["propertyDict"].(*schema.PropertyDict)
if dict != nil {
    batch, pool := payloadPoolManager.Borrow(dict)
    batch.DeviceName = deviceName
    batch.Timestamp = nowTs
    if err := binaryTransform.DecodePropertiesIntoPayload(logger, dict, deviceMsgInverter, batch); err != nil {
        pool.Put(batch)
        continue
    }
    if batch.HasValues() {
        result = append(result, map[string]any{
            "sinkType":   "tdengine",
            "recordType": "propertyTypedBatch",
            "productID":  subProductID,
            "deviceName": deviceName,
            "timestamp":  nowTs,
            "batch":      batch,
            "dict":       dict,
            "optional":   subRuntimeMeta,
            "_pool":      pool,  // sink 写入完成后归还
        })
    } else {
        pool.Put(batch)
    }
} else {
    // 旧路径完全保留
}
```

### 4.3 修改 `tdengine_sql.go`
新增 `BuildPropertySQLFromBatch`：

```go
func BuildPropertySQLFromBatch(database string, record map[string]any) ([]string, []any, error)
```

按 dict.Points[ref.PointID] 恢复 ColumnSQL，按 Kind 从 arena 读值。每个非空 ModulePayload 生成一个 SQL fragment。必须处理 `default` 分支返回 error。

### 4.4 修改 `tdengine_sink.go`
`collectList` 中新增 `propertyTypedBatch` 分支：

```go
case "propertyTypedBatch":
    sqlClauses, args, err = BuildPropertySQLFromBatch(s.cfg.Database, record)
```

flush 后归还 batch：

```go
if pool, ok := record["_pool"].(*payload.ModelPayloadPool); ok {
    pool.Put(record["batch"].(*payload.ModulePayloadBatch))
}
```

### 4.4 测试
+ `handle_push_data_test.go`：构造含 `propertyDict` 的 oneSchema，验证新路径输出 `propertyTypedBatch` record
+ `tdengine_sql_test.go`：验证 `BuildPropertySQLFromBatch` 输出的 SQL 与 `BuildPropertySQL` 语义一致
