# 云端 MQTT 接入 Broker 成本分析

> 本文承接 [百万级设备 MQTT 接入层架构设计](./1.cloud-mqtt-gateway-architecture.md)，估算百万逆变器接入层在云厂商 Redis / Kafka / ECS 上的年度成本，并对比自研 Broker 与购买 EMQX Enterprise / BYOC license 的成本区间。

---

## 1. 估算结论

估算日期：

```text
2026-05-19
```

汇率假设：

```text
1 USD ≈ 6.8 CNY
```

只算接入层、控制面和 raw log：

```text
MQTT Broker ECS / EC2
Kafka / Redpanda / ApsaraMQ for Kafka / MSK
Redis / Tair / ElastiCache
etcd / NATS → Redis（和 presence 同库）
Command Service
SLB / NLB
基础监控日志
```

不包含：

```text
时序库
OLAP
告警系统
业务 DB 大表
Modbus Decoder 大规模计算
研发人力
公网大流量
专线 / 安全合规 / 技术支持
税费
```

年度粗估：

| 方案 | 云厂商 | 年度成本 USD | 年度成本 RMB |
|---|---|---:|---:|
| 自研 MQTT Broker | 阿里云 | 80k ~ 200k | 约 54 万 ~ 136 万 |
| 自研 MQTT Broker | AWS | 220k ~ 360k | 约 150 万 ~ 245 万 |
| EMQX Enterprise / BYOC + 云资源 | 阿里云 | 120k ~ 480k | 约 82 万 ~ 326 万 |
| EMQX Enterprise / BYOC + 云资源 | AWS | 270k ~ 660k | 约 184 万 ~ 449 万 |

关键判断：

```text
1. Kafka / raw log 是主要云资源成本。
2. Presence Registry / Redis 通常不是主要成本。
3. 自研方案云账单更低，但第一年应额外计算研发、压测和故障风险成本。
4. EMQX license 如果低于 150k USD/year，第一年 TCO 可能更有吸引力。
5. EMQX license 如果高于 300k USD/year，自研经济性会明显增强。
```

## 2. 业务容量假设

基础模型：

```text
设备数：1,000,000
payload：3KB
上报周期：5 分钟
白天在线窗口：12 小时 / 天
raw 数据量：约 432GB/day
```

计算：

```text
每台设备每天上报次数 = 12h * 60 / 5 = 144
总消息数 = 1,000,000 * 144 = 144,000,000 msg/day
raw 数据量 = 144,000,000 * 3KB ≈ 432GB/day
```

保留周期：

| 保留周期 | logical raw log | 三副本物理写入 / 存储量 |
|---|---:|---:|
| 7 天 | 约 3.0TB | 约 9.1TB |
| 30 天 | 约 13.0TB | 约 38.9TB |

峰值吞吐：

| 场景 | msg/s | raw 入口流量 |
|---|---:|---:|
| 均匀打散到 5 分钟 | 3333/s | 约 10MB/s |
| 挤在 1 分钟 | 16667/s | 约 50MB/s |
| 挤在 10 秒 | 100000/s | 约 300MB/s |
| 挤在 1 秒 | 1000000/s | 约 3GB/s |

成本估算重点看：

```text
1. Kafka 写入峰值能力。
2. raw log 保留周期。
3. MQTT Broker 连接密度。
4. 是否需要硬扛同步上报峰值。
```

## 3. 自研方案成本模型

### 3.1 组件清单

推荐生产形态：

```text
MQTT Broker 集群
Kafka / Redpanda raw log
Redis / Tair presence
etcd / NATS → Redis（和 presence 同库） broker registry + service discovery
Command Service
SLB / NLB
基础日志和监控
```

不建议把 Broker 做成本地状态存储节点，因此 Broker ECS / EC2 主要承担：

```text
长连接
TLS
MQTT codec
基础认证
raw log append
presence 注册
本地下行 PUBLISH
```

### 3.2 阿里云年度粗估

阿里云估算以 ApsaraMQ for Kafka Serverless、Tair / Redis、ECS 为参考。

| 成本项 | 低估 | 常规 | 高峰预留 |
|---|---:|---:|---:|
| ApsaraMQ for Kafka / raw log | 30k | 45k | 90k |
| Tair / Redis Presence | 2k | 8k | 20k |
| MQTT Broker ECS | 30k | 60k | 90k |
| Command Service / etcd / NATS → Redis（和 presence 同库） | 5k | 12k | 25k |
| SLB / 日志 / 监控 / 备份余量 | 13k | 35k | 75k |
| 合计 USD/year | 80k | 160k | 300k |
| 合计 RMB/year | 约 54 万 | 约 109 万 | 约 204 万 |

建议预算：

```text
常规预算：80k ~ 200k USD/year
高峰预算：150k ~ 300k USD/year
```

注意：

```text
如果 ApsaraMQ for Kafka 存储按 logical message storage 计费，成本较低。
如果实际按三副本物理存储口径或额外吞吐预留计费，应把 storage / capacity 部分上调。
```

### 3.3 AWS 年度粗估

AWS 估算以 Amazon MSK、ElastiCache、EC2 为参考。

| 成本项 | 低估 | 常规 | 高峰预留 |
|---|---:|---:|---:|
| Amazon MSK / raw log | 70k | 120k | 220k |
| ElastiCache Presence | 10k | 20k | 40k |
| MQTT Broker EC2 | 70k | 100k | 160k |
| Command Service / etcd / NATS → Redis（和 presence 同库） | 10k | 25k | 45k |
| NLB / 日志 / 监控 / EBS / 备份余量 | 60k | 95k | 135k |
| 合计 USD/year | 220k | 360k | 600k |
| 合计 RMB/year | 约 150 万 | 约 245 万 | 约 408 万 |

建议预算：

```text
常规预算：220k ~ 360k USD/year
高峰预算：400k ~ 600k USD/year
```

AWS 成本更高的主要原因：

```text
1. MSK broker instance + EBS storage 成本较高。
2. 多 AZ 访问、日志、监控、EBS 和网络项容易累积。
3. 如果为了 10 秒级同步上报峰值预留资源，broker 和 Kafka 都要明显放大。
```

## 4. EMQX Enterprise / BYOC 成本模型

EMQX 官方公开页显示：

```text
Self-managed Enterprise：Custom annual subscription
BYOC：Custom，需要联系销售
License 与连接数 / TPS 等容量相关
```

因此 100 万连接 license 不能按公开固定价格精确估算，只能做情景分析。

### 4.1 EMQX 替代哪些自研能力

使用 EMQX 可以减少或替代：

```text
MQTT 协议栈
Broker 集群治理
订阅树
共享订阅
session takeover
监控和运维工具
认证 / ACL / 插件生态
部分下行路由能力
```

但不一定替代：

```text
Kafka raw log
Modbus Decoder
Command Service 命令状态机
业务 APP ACK
时序库 / OLAP
业务设备档案
```

如果仍按当前设计保留 Kafka 作为 durable raw log 主链路，Kafka 成本不会因为使用 EMQX 消失。

### 4.2 License 情景

| EMQX License 假设 | 阿里云总成本 USD/year | 阿里云 RMB/year | AWS 总成本 USD/year | AWS RMB/year |
|---:|---:|---:|---:|---:|
| 50k | 120k ~ 230k | 约 82 万 ~ 156 万 | 270k ~ 410k | 约 184 万 ~ 279 万 |
| 150k | 220k ~ 330k | 约 150 万 ~ 224 万 | 370k ~ 510k | 约 252 万 ~ 347 万 |
| 300k | 370k ~ 480k | 约 252 万 ~ 326 万 | 520k ~ 660k | 约 354 万 ~ 449 万 |

这些数字包括：

```text
EMQX license
运行 EMQX 的 ECS / EC2
Kafka raw log
Redis / DB / Command Service / 基础控制面
SLB / 监控 / 日志粗略余量
```

不包括：

```text
EMQX 原厂专业服务
高级支持附加包
跨区域灾备
时序库 / OLAP
```

### 4.3 何时倾向 EMQX

倾向 EMQX：

```text
1. 团队不想承担 MQTT Broker 协议和集群风险。
2. 需要 MQTT 5、共享订阅、保留消息、规则引擎、丰富认证 ACL。
3. 需要厂商支持和生产事故兜底。
4. EMQX 100 万连接 license 低于 150k USD/year。
```

倾向自研：

```text
1. 业务协议边界非常收敛，只做逆变器 telemetry ingress。
2. 上行必须严格以 Kafka / Redpanda durable raw log ack 作为 MQTT QoS1 PUBACK 承诺点。
3. 不需要通用 MQTT Broker 能力。
4. 团队有能力做长连接、压测、故障演练和线上运维。
5. EMQX license 高于 300k USD/year。
```

## 5. 成本敏感项

### 5.1 上报打散

是否打散上报，直接决定 Kafka 和 Broker 峰值成本。

```text
均匀打散到 5 分钟：约 10MB/s。
挤在 1 分钟：约 50MB/s。
挤在 10 秒：约 300MB/s。
挤在 1 秒：约 3GB/s。
```

建议：

```text
设备侧必须做 jitter。
Broker 侧必须做背压。
Kafka / Redpanda 只按合理峰值预留，不为 1 秒全量同步上报买单。
```

### 5.2 Raw Log 保留周期

保留周期从 7 天变成 30 天，logical 存储约从 3TB 变成 13TB。

建议：

```text
raw binary 热保留：7 天。
长期审计：转储到对象存储。
解码后数据进入时序库 / OLAP。
```

### 5.3 QoS0 是否 100% 入 raw log

如果 QoS0 也要求 100% 进入 durable raw log，那么成本按可靠链路规划：

```text
Kafka / Redpanda 写入峰值提升。
Broker append queue 和重试压力提升。
存储保留成本提升。
```

如果允许压力水位下丢弃 QoS0，接入层成本可以显著降低。

### 5.4 云厂商区域

不同地域差异明显：

```text
中国大陆、香港、新加坡、美国、欧洲价格不同。
跨 AZ、跨 VPC、PrivateLink、公网出口都可能额外计费。
```

最终预算必须以目标地域的云厂商计算器为准。

## 6. 推荐预算口径

第一版立项预算建议：

| 方案 | 年度预算建议 |
|---|---:|
| 阿里云自研 | 100k ~ 200k USD |
| AWS 自研 | 250k ~ 400k USD |
| 阿里云 + EMQX | 200k ~ 400k USD |
| AWS + EMQX | 350k ~ 650k USD |

折合人民币：

| 方案 | 年度预算建议 |
|---|---:|
| 阿里云自研 | 约 68 万 ~ 136 万 |
| AWS 自研 | 约 170 万 ~ 272 万 |
| 阿里云 + EMQX | 约 136 万 ~ 272 万 |
| AWS + EMQX | 约 238 万 ~ 442 万 |

工程建议：

```text
1. 先用阿里云或 AWS 计算器按目标地域重算一次。
2. 用 10 万连接压测推导 Broker 单节点容量。
3. 用 10MB/s、50MB/s、300MB/s 三档压测 Kafka / Redpanda。
4. 再按压测结果确定 Broker 节点数和 Kafka 规格。
5. 同步向 EMQX 询价 100 万连接 + 目标 TPS 的 Enterprise / BYOC license。
```
