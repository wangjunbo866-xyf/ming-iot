# MQTT Gateway DevServer 配置设计

> 目标：在 `mqtt-gateway` 中新增一个类似 go-zero `DevServer` 的开发诊断配置，用同一个配置段开启或关闭 Prometheus metrics、OpenTelemetry tracing 和 pprof，替换当前单独的 `pprofAddr` 配置。

---

## 1. 背景

`things` 服务当前使用 go-zero v1.8.4。go-zero 的 `ServiceConf` 中包含：

- `Prometheus`：旧的独立 Prometheus agent 配置。
- `Telemetry`：OpenTelemetry tracing 配置。
- `DevServer`：内置开发诊断 HTTP server，字段包括 `Enabled`、`Host`、`Port`、`MetricsPath`、`HealthPath`、`EnableMetrics`、`EnablePprof`、`HealthResponse`。

go-zero `DevServer` 的核心行为是启动一个内部 HTTP server：

- `/healthz`：健康检查。
- `/metrics`：Prometheus scrape 入口，受 `EnableMetrics` 控制。
- `/debug/pprof/*`：pprof 入口，受 `EnablePprof` 控制。
- `/`：返回已注册路由列表，便于排障。

`mqtt-gateway` 目前不是 go-zero 服务，配置由 `gopkg.in/yaml.v3` 直接解析。当前只有：

```yaml
pprofAddr: "127.0.0.1:6060"
```

并通过 `internal/profiling` 在 `-tags pprof` 构建时启动 `/debug/pprof/*`。服务还没有 Prometheus endpoint，也没有 tracing 初始化入口。

本设计不把 `mqtt-gateway` 改造成 go-zero 服务，而是在当前轻量启动模型下复刻 go-zero `DevServer` 的配置体验，并扩展 `EnableTelemetry`。

---

## 2. 设计目标

| 目标 | 说明 |
|---|---|
| 单一配置入口 | 用 `DevServer` 统一管理 metrics、telemetry、pprof，而不是分散在多个顶层配置项。 |
| 模仿 go-zero 字段 | 保留 `Enabled`、`Host`、`Port`、`MetricsPath`、`HealthPath`、`EnableMetrics`、`EnablePprof`、`HealthResponse` 等字段。 |
| 增加 telemetry 开关 | 新增 `EnableTelemetry` 和嵌套 `Telemetry`，由 `DevServer` 控制 tracing 是否启动。 |
| 兼容现有配置 | 保留 `pprofAddr` 的兼容读取，避免现有配置立即失效。 |
| 安全默认 | pprof 继续受 build tag 门控，默认只建议绑定 `127.0.0.1` 或受控管理网段。 |
| 可测试 | 配置默认值、路由开关、pprof build tag、优雅关闭都要有单元测试覆盖。 |

---

## 3. 非目标

第一阶段不做：

| 非目标 | 原因 |
|---|---|
| 引入 go-zero 框架启动链路 | `mqtt-gateway` 当前是专用 broker，直接使用 go-zero `ServiceConf` 会引入不必要的服务模型变化。 |
| 依赖 go-zero internal devserver | go-zero 的 `internal/devserver` 不能被外部模块直接导入。 |
| 一次性补齐全部业务指标 | 本次目标是 DevServer 配置和 endpoint 框架；业务指标按红线文档逐步注册，但必须预留低基数注册入口。 |
| 让 telemetry 影响 broker 可用性 | tracing exporter 不可达不能拖垮设备接入。 |
| 对公网暴露 pprof | pprof 会泄露堆栈和内存信息，只允许 localhost 或管理网访问。 |

---

## 4. 推荐方案

推荐新增 `internal/devserver` 包，独立实现一个 broker 专用 DevServer：

```text
cmd/gateway/main.go
  -> config.Load()
  -> existing broker startup
  -> MQTT listener ready
  -> devserver.Start(cfg.DevServer, log)
       -> health route
       -> prometheus route
       -> optional pprof routes
       -> optional tracing provider
  -> shutdown signal
  -> devserver.Stop()
```

不推荐直接引入 go-zero `ServiceConf`。原因是 `mqtt-gateway` 的启动顺序、依赖 fail-fast、队列红线和 pprof build tag 都已经是专用设计；复刻配置语义即可，不需要改变服务框架。

### 4.1 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 自研 `internal/devserver` | 最小改动，保留当前 broker 启动模型；可继续 build tag 门控 pprof；字段可贴近 go-zero。 | 需要维护少量 HTTP server 与 tracing 初始化代码。 | 推荐。 |
| 引入 go-zero `ServiceConf` | 字段和 go-zero 完全一致。 | 会改变启动链路，引入 logx/proc/stat 等行为；`internal/devserver` 仍不能直接导入。 | 不推荐。 |
| 继续拆成 `pprofAddr`、`prometheus`、`telemetry` | 实现简单。 | 不符合“DevServer 统一开关”的目标，配置体验和 go-zero 不一致。 | 不推荐。 |

---

## 5. 配置设计

新增顶层 `DevServer` 配置段，字段采用 go-zero 风格的大写 key，便于和 `things` 服务保持一致。

```yaml
# DevServer 是 broker 的内部诊断 HTTP server。
# 生产环境建议绑定 127.0.0.1 或受控管理网段，再由 sidecar / ingress / port-forward 暴露给运维面。
DevServer:
  Enabled: true
  Host: "127.0.0.1"
  Port: 6060
  MetricsPath: "/metrics"
  HealthPath: "/healthz"
  EnableMetrics: true
  EnableTelemetry: false
  EnablePprof: false
  HealthResponse: "OK"
  Telemetry:
    Name: "mqtt-gateway"
    Endpoint: "http://127.0.0.1:14268/api/traces"
    Sampler: 1.0
    Batcher: "jaeger"
    OtlpHeaders: {}
    OtlpHttpPath: ""
    OtlpHttpSecure: false
```

字段说明：

| 字段 | 默认值 | 说明 |
|---|---:|---|
| `Enabled` | `true`，仅当 `DevServer` 段存在时生效 | 总开关。为 `false` 时不启动 HTTP server，也不启动 telemetry。 |
| `Host` | `127.0.0.1` | 监听地址。与 go-zero 的空 host 不同，broker 默认收紧到本机。 |
| `Port` | `6060` | 监听端口。 |
| `MetricsPath` | `/metrics` | Prometheus scrape 路径。 |
| `HealthPath` | `/healthz` | 健康检查路径。 |
| `EnableMetrics` | `true` | Prometheus metrics 开关，对应 go-zero 的 `EnableMetrics`。 |
| `EnableTelemetry` | `false` | broker 扩展字段，控制 tracing provider 是否初始化。 |
| `EnablePprof` | `true` | pprof 路由开关；只有 `-tags pprof` 构建时才真正注册路由。 |
| `HealthResponse` | `OK` | 健康检查响应体。 |
| `Telemetry` | 空 | tracing exporter 配置，字段对齐 go-zero `trace.Config`。 |

### 5.1 默认值策略

使用指针识别 `DevServer` 是否存在：

```go
type Config struct {
    PprofAddr string           `yaml:"pprofAddr"` // deprecated
    DevServer *DevServerConfig `yaml:"DevServer"`
}
```

规则：

1. `DevServer` 不存在，且 `pprofAddr` 为空：不启动 DevServer。
2. `DevServer` 存在，且 `Enabled` 未显式设置：按 go-zero 语义默认为 `true`。
3. `DevServer` 存在，`EnableMetrics` / `EnablePprof` 未显式设置：默认为 `true`。
4. `EnableTelemetry` 默认为 `false`，必须显式开启。
5. `Host` 默认使用 `127.0.0.1`，这是 broker 安全加固点。

### 5.2 兼容 `pprofAddr`

当前配置：

```yaml
pprofAddr: "127.0.0.1:6060"
```

兼容策略：

| 场景 | 行为 |
|---|---|
| 只配置 `pprofAddr` | 转换为 legacy DevServer：只开启 pprof，不开启 metrics 和 telemetry。 |
| 同时配置 `DevServer` 和 `pprofAddr` | `DevServer` 优先，`pprofAddr` 仅打印 deprecated warning。 |
| `pprofAddr` 为空 | 不触发 legacy 行为。 |

legacy 转换后的等价配置：

```yaml
DevServer:
  Enabled: true
  Host: "127.0.0.1"
  Port: 6060
  EnableMetrics: false
  EnableTelemetry: false
  EnablePprof: true
```

## 6. 模块设计

### 6.1 `internal/config`

新增结构：

```go
type DevServerConfig struct {
    Enabled        bool            `yaml:"Enabled"`
    Host           string          `yaml:"Host"`
    Port           int             `yaml:"Port"`
    MetricsPath    string          `yaml:"MetricsPath"`
    HealthPath     string          `yaml:"HealthPath"`
    EnableMetrics  bool            `yaml:"EnableMetrics"`
    EnableTelemetry bool           `yaml:"EnableTelemetry"`
    EnablePprof    bool            `yaml:"EnablePprof"`
    HealthResponse string          `yaml:"HealthResponse"`
    Telemetry      TelemetryConfig `yaml:"Telemetry"`
}

type TelemetryConfig struct {
    Name           string            `yaml:"Name"`
    Endpoint       string            `yaml:"Endpoint"`
    Sampler        float64           `yaml:"Sampler"`
    Batcher        string            `yaml:"Batcher"`
    OtlpHeaders    map[string]string `yaml:"OtlpHeaders"`
    OtlpHttpPath   string            `yaml:"OtlpHttpPath"`
    OtlpHttpSecure bool              `yaml:"OtlpHttpSecure"`
}
```

`DevServerConfig` 实现 `UnmarshalYAML`，先填默认值再 decode，以支持 bool 默认 `true`：

```go
DevServerConfig{
    Enabled: true,
    Host: "127.0.0.1",
    Port: 6060,
    MetricsPath: "/metrics",
    HealthPath: "/healthz",
    EnableMetrics: true,
    EnablePprof: true,
    HealthResponse: "OK",
    Telemetry: TelemetryConfig{
        Name: "mqtt-gateway",
        Sampler: 1.0,
        Batcher: "jaeger",
    },
}
```

校验规则：

- `Port` 必须在 `0..65535`。`0` 只用于测试临时端口。
- `MetricsPath` 和 `HealthPath` 必须以 `/` 开头。
- `HealthPath`、`MetricsPath` 不能重复。
- `EnableTelemetry=true` 时：
  - `Telemetry.Name` 为空则使用 `brokerID` 或默认 `mqtt-gateway`。
  - `Sampler` 范围为 `0.0..1.0`。
  - `Batcher` 支持 `jaeger|zipkin|otlpgrpc|otlphttp|file`。
  - `Endpoint` 为空时允许启动无 exporter tracer provider，但需要打印 warning。

### 6.2 `internal/devserver`

新增 broker 专用 DevServer：

```text
internal/devserver/
  server.go          # HTTP server、routes、Start/Stop
  pprof_enabled.go   # go:build pprof，注册 pprof routes
  pprof_disabled.go  # go:build !pprof，禁用 pprof routes 并返回状态
  telemetry.go       # tracing provider 初始化与 shutdown
```

推荐接口：

```go
type Config struct {
    Enabled         bool
    Host            string
    Port            int
    MetricsPath     string
    HealthPath      string
    EnableMetrics   bool
    EnableTelemetry bool
    EnablePprof     bool
    HealthResponse  string
    Telemetry       TelemetryConfig
}

type Server struct {
    // 持有 http.Server、listener、tracer shutdown。
}

func Start(c Config, log *slog.Logger) (*Server, error)
func (s *Server) Stop(ctx context.Context) error
func (s *Server) Addr() string
```

启动行为：

1. `Enabled=false`：返回 no-op server。
2. 先 `net.Listen`，监听失败直接返回错误，避免配置了 DevServer 但实际不可用。
3. 注册 `/`、`HealthPath`、可选 `MetricsPath`、可选 `/debug/pprof/*`。
4. 如果 `EnableTelemetry=true`，初始化 tracing provider。
5. `http.Server` 设置 `ReadHeaderTimeout`，防止慢请求占用诊断端口。
6. shutdown 时先停 HTTP server，再 shutdown tracing provider。

### 6.3 Prometheus

引入 `github.com/prometheus/client_golang/prometheus/promhttp`。

第一阶段至少暴露：

- Go runtime metrics。
- process metrics。
- 后续 broker 自定义低基数指标的注册入口。

自定义指标必须遵守红线：

- 禁止 device_id、client_id、username、topic 原文作为 label。
- queue、latency、drop、connection 等指标使用固定 label 集。
- metrics 采集不能使用无界队列。

### 6.4 Telemetry

Telemetry 使用 OpenTelemetry SDK 直接实现，配置字段对齐 go-zero `trace.Config`。

行为约束：

- `EnableTelemetry=false` 时完全不初始化 tracing provider。
- exporter 初始化失败只记录 warning，不阻断 broker 启动。
- tracing span 只在低频或关键路径按采样率记录，不在每条高频 PUBLISH 上无节制创建高基数 span。
- span attribute 禁止包含 device_id、payload、认证密码等敏感或高基数字段。
- 退出时调用 tracer provider shutdown，最多等待 2 秒。

### 6.5 pprof

保留现有 build tag 策略：

```bash
go build -tags pprof ./...
go test  -tags pprof ./internal/devserver
```

规则：

- `EnablePprof=false`：不注册 pprof routes。
- `EnablePprof=true` 且未使用 `-tags pprof`：不注册 pprof routes，打印 `pprof not compiled in`。
- `EnablePprof=true` 且使用 `-tags pprof`：注册 `/debug/pprof/*`。
- 默认配置示例中生产建议 `EnablePprof: false`，压测和故障排查时再开启。

## 7. 启动与关闭顺序

推荐在 `cmd/gateway/main.go` 中：

1. 加载配置并完成默认值处理。
2. 初始化 DB、auth queue、Kafka、Redis、presence、MQTT listener。
3. MQTT listener 启动成功后启动 DevServer。
4. 收到退出信号后按逆构造序关闭。

关闭顺序建议：

```text
DevServer HTTP server + telemetry provider
  -> MQTT listener
  -> Redis / ingest / Kafka / auth / DB
```

由于 DevServer 在 broker ready 后启动，第一阶段 `/healthz` 返回 `HealthResponse` 即表示当前进程已经完成启动。后续如果需要区分更细状态，可以在 `devserver.Server` 中预留 readiness 状态：

```text
starting -> ready -> shutting_down
```

第一阶段可以保持简单：DevServer 启动成功后 `/healthz` 返回 `HealthResponse`。

## 8. 配置迁移示例

迁移前：

```yaml
pprofAddr: "127.0.0.1:6060"
```

迁移后：

```yaml
DevServer:
  Enabled: true
  Host: "127.0.0.1"
  Port: 6060
  MetricsPath: "/metrics"
  HealthPath: "/healthz"
  EnableMetrics: true
  EnableTelemetry: false
  EnablePprof: false
  HealthResponse: "OK"
```

压测 / 故障排查时：

```yaml
DevServer:
  Enabled: true
  Host: "127.0.0.1"
  Port: 6060
  MetricsPath: "/metrics"
  HealthPath: "/healthz"
  EnableMetrics: true
  EnableTelemetry: true
  EnablePprof: true
  HealthResponse: "OK"
  Telemetry:
    Name: "mqtt-gateway"
    Endpoint: "http://127.0.0.1:14268/api/traces"
    Sampler: 0.01
    Batcher: "jaeger"
```

验收命令：

```bash
curl -s http://127.0.0.1:6060/healthz
curl -s http://127.0.0.1:6060/metrics
curl -s http://127.0.0.1:6060/debug/pprof/
```

## 9. 测试计划

### 9.1 配置测试

覆盖 `internal/config`：

- `DevServer` 缺失时不启动。
- `DevServer: {}` 时填充默认值。
- `Enabled:false` 时禁用全部诊断能力。
- `EnableMetrics:false`、`EnableTelemetry:false`、`EnablePprof:false` 分别生效。
- `pprofAddr` legacy 配置转换为只开启 pprof 的 DevServer。
- `DevServer` 和 `pprofAddr` 同时存在时 `DevServer` 优先。
- 非法 path、非法 port、非法 sampler 返回清晰错误。

### 9.2 DevServer 路由测试

覆盖 `internal/devserver`：

- `GET /` 返回已注册路由列表。
- `GET /healthz` 返回配置的 `HealthResponse`。
- `EnableMetrics=true` 时 `/metrics` 返回 200。
- `EnableMetrics=false` 时 `/metrics` 返回 404。
- `EnablePprof=false` 时 `/debug/pprof/` 返回 404。
- `-tags pprof` 下 `EnablePprof=true` 时 `/debug/pprof/` 返回 200。
- `Stop()` 可重复调用且不 panic。

### 9.3 集成验证

基础验证：

```bash
cd mqtt-gateway
go test ./...
go test -tags pprof ./...
```

手工验证：

```bash
go run -tags pprof ./cmd/gateway -f etc/gateway.yaml
curl -i http://127.0.0.1:6060/healthz
curl -i http://127.0.0.1:6060/metrics
curl -i http://127.0.0.1:6060/debug/pprof/
```

## 10. 风险与约束

| 风险 | 应对 |
|---|---|
| pprof 被公网访问 | 默认示例绑定 `127.0.0.1`；文档和校验中强调禁止生产绑定 `0.0.0.0`。 |
| metrics label 高基数导致内存膨胀 | 自定义指标必须经过红线检查，禁止 device_id/client_id/topic 原文 label。 |
| tracing 对高频 PUBLISH 产生额外开销 | 默认 `EnableTelemetry=false`；开启时采样率建议小于等于 `0.01`，并限制 span attribute。 |
| DevServer 端口冲突 | `Enabled=true` 且监听失败时启动失败，避免“以为开了但没开”。 |
| 兼容配置混乱 | `pprofAddr` 只做 deprecated 兼容；新文档和示例统一使用 `DevServer`。 |

---

## 11. 实施边界

本设计对应一次小步实现：

1. 新增配置结构、默认值、校验和 legacy `pprofAddr` 转换。
2. 新增 `internal/devserver`，承载 health、metrics、pprof、telemetry 初始化。
3. 修改 `cmd/gateway/main.go`，用 `DevServer` 替换当前 `profiling.Start(cfg.PprofAddr)`。
4. 更新 `etc/gateway.yaml` 示例。
5. 补齐配置、路由和 pprof build tag 测试。

完成后，`mqtt-gateway` 可以通过一个 `DevServer` 配置统一控制：

```text
Prometheus metrics: DevServer.EnableMetrics
Telemetry tracing:  DevServer.EnableTelemetry
pprof:              DevServer.EnablePprof
```
