# 三环境配置文件设计
日期：2026-05-27

## 1. 目标
项目需要同时支持三类环境：

| 环境 | 运行方式 | 目标 |
| --- | --- | --- |
| 本地开发环境 | Docker Compose | 快速启动、便于调试、允许低成本依赖和直连模式 |
| 压测环境 | ACK | 接近生产拓扑、可观测、可扩缩、可反复清理 |
| 生产环境 | ACK | 高可用、安全、配置可审计、发布可回滚 |


配置设计目标：

1. 不在 Git 中保存真实密码、AK、JWT secret、短信/OSS 密钥。
2. 三环境使用同一套配置结构，差异只放在环境 overlay。
3. 本地开发可以保留 `direct` 模式，ACK 压测/生产统一使用 `grpc + k8s://`。
4. 设备 MQTT 入口短期统一使用 EMQX `5.8+` 开源版，NATS 只作为内部事件总线；长期版本路线为面向逆变器设备场景的简化自研 MQTT Broker。
5. `common.yaml` 放公共依赖，服务专属 YAML 只放端口、服务名和 RPC client。
6. Helm/Compose 只负责挂载配置和注入 Secret，不把复杂业务配置写死在部署模板中。

## 2. 现有配置加载规则
代码中已有几个重要机制：

| 机制 | 影响 |
| --- | --- |
| `saas/share/utils/conf.go` 会先读同目录 `common.yaml` | 每个服务目录必须保证 `common.yaml` 和服务 YAML 成对挂载 |
| `os.ExpandEnv()` 会在解析 YAML 前展开环境变量 | YAML 可以写 `${DB_HOST}`、`${REDIS_PASSWORD}` 等 |
| `ConfMustLoad("etc/*.yaml")` 优先读取当前工作目录 | 容器内推荐统一挂载到 `/app/etc`，`WORKDIR=/app` |
| `confPrefix/confSuffix` 可改文件名 | 新配置不推荐依赖它，避免路径和文件名过度隐式 |
| go-zero `zrpc.RpcClientConf` 支持 `Target` | ACK 可用 `Target: k8s://namespace/service:port` 替代业务 etcd |


结论：新配置应尽量使用“完整挂载 `/app/etc`”而不是依赖镜像内置配置和 `confSuffix` 魔法。

## 4. 三环境差异矩阵
| 配置项 | 本地 Docker Compose | ACK 压测 | ACK 生产 |
| --- | --- | --- | --- |
| 服务发现 | 优先 `direct`，可选 Compose DNS/etcd | `grpc + k8s://auxsol-test/<svc>:<port>` | `grpc + k8s://auxsol-prod/<svc>:<port>` |
| PostgreSQL | 本地 `postgres` 容器 | 独立 RDS/测试库 | 独立 RDS/生产库 |
| Redis | 本地 `redis` 容器 | ApsaraDB Redis 测试实例 | ApsaraDB Redis 生产实例 |
| MQTT Broker | 本地 EMQX `5.8+` 开源版容器 | ACK EMQX `5.8+` 开源版 + NLB；3 个 core 节点起步，最多 5 个 | 短期 ACK EMQX `5.8+` 开源版 + NLB；3 个 core 节点起步，最多 5 个，长期自研 MQTT Broker |
| NATS | 本地 NATS 容器 | ACK NATS/JetStream | ACK NATS/JetStream |
| TDengine | 本地 TDengine 容器 | ACK TDengine 或压测专用实例 | ACK TDengine/生产实例 |
| OSS | `local` 或 MinIO | 测试 Bucket | 生产 Bucket |
| 日志 | console/plain/debug | console/json/info | console/json/info 或 warn |
| Prometheus | 可关闭 | 必开 | 必开 |
| Secret 来源 | `.env` 本地文件 | K8s Secret/External Secrets | K8s Secret/External Secrets + KMS |
| 镜像 tag | `1.0.0-dev` | git sha，不可变 | semver + git sha，必要时 pin digest |


## 5. 本地 Docker Compose 配置
本地配置以“开发效率”为主，允许部分 RPC 使用 `direct`，减少开发者需要同时启动的服务数量。

推荐规则：

1. 依赖容器统一使用服务名：`postgres`、`redis`、`nats`、`emqx`、`tdengine`。
2. 默认启动 EMQX `5.8+` 开源版，eKuiper MQTT source 指向 `tcp://emqx:1883`，不要再把 NATS 1883 当设备入口。
3. API Gateway 如果内嵌 direct RPC，使用 `Mode: direct, RunProxy: true`。
4. 如果开发者要验证微服务拆分，可切换到 `Mode: grpc` + Compose DNS endpoints，但这不是默认路径。
5. 本地 `.env` 只放开发密码，不能复制压测/生产 Secret。

本地 `saas-api-gateway` RPC 示例：

```yaml
SysRpc:
  Enable: true
  Mode: direct
  RunProxy: true
  Conf:
    Timeout: 1000000
TimedJobRpc:
  Enable: true
  Mode: direct
  RunProxy: true
  Conf:
    Timeout: 1000000
TimedSchedulerRpc:
  Enable: true
  Mode: direct
  RunProxy: true
  Conf:
    Timeout: 1000000
```

本地 `iot-api-gateway` 可混合使用：

```yaml
ThingsRpc:
  Enable: true
  Mode: direct
  RunProxy: true
  Conf:
    Timeout: 1000000
ProtocolSyncRpc:
  Enable: true
  Mode: direct
  RunProxy: true
  Conf:
    Timeout: 1000000
SysRpc:
  Enable: true
  Mode: grpc
  Conf:
    Timeout: 1000000
    Endpoints:
      - saas-api-gateway:8002
```

## 6. ACK 压测环境配置
压测环境目标是接近生产，同时允许快速调参。

推荐规则：

1. 不自建业务 etcd，默认使用 go-zero `k8s://` resolver。
2. 每个 RPC 服务独立 Deployment + ClusterIP Service。
3. API/RPC Pod 的 ServiceAccount 必须能 `get/list/watch endpoints`。
4. 所有配置通过 ConfigMap + Secret 注入，禁止使用镜像内置开发配置。
5. 日志使用 json/info，必要时针对单个服务临时调 debug。
6. 压测环境允许更短的数据保留、更低规格 RDS/Redis，但拓扑要与生产一致。
7. EMQX `5.8+` 开源版的压测结果要作为后续自研 MQTT Broker 的兼容和容量基线；ACK 环境只规划 core 节点，建议 3 个，最多 5 个。

ACK 压测 RPC 示例：

```yaml
SysRpc:
  Enable: true
  Mode: grpc
  Conf:
    Timeout: 1000000
    Target: k8s://auxsol-test/system-rpc:8002
TimedJobRpc:
  Enable: true
  Mode: grpc
  Conf:
    Timeout: 1000000
    Target: k8s://auxsol-test/timedjob-rpc:8003
TimedSchedulerRpc:
  Enable: true
  Mode: grpc
  Conf:
    Timeout: 1000000
    Target: k8s://auxsol-test/timedscheduler-rpc:8005
```

## 7. ACK 生产环境配置
生产配置在压测配置基础上收紧安全和稳定性。

推荐规则：

1. `Mode: grpc` 是唯一允许的跨服务调用方式。
2. 不允许 `Mode: direct` 出现在生产 ConfigMap 中。
3. 所有 Secret 由 Secret Manager/KMS/External Secrets 同步，不手写到 Helm values。
4. RDS/Redis/OSS/NATS/EMQX/TDengine 必须使用独立生产账号和最小权限；长期替换为自研 MQTT Broker 时，设备侧端口、topic 和认证契约应保持稳定。
5. 日志和指标默认打开，敏感字段必须脱敏。
6. 镜像 tag 必须不可变，推荐同时记录 digest。
7. 生产回滚以 Helm revision + Secret 版本为单位。

生产 RPC 示例：

```yaml
SysRpc:
  Enable: true
  Mode: grpc
  Conf:
    Timeout: 5000
    Target: k8s://auxsol-prod/system-rpc:8002
```

## 8. 配置模板文件说明
本目录下按环境目录给出模板：

| 模板 | 用途 |
| --- | --- |
| `local-docker-compose/.env.example` | 本地 Compose `.env` 模板 |
| `local-docker-compose/ekuiper.env` | 本地 eKuiper 环境变量模板 |
| `local-docker-compose/etc/*.yaml` | 本地固定文件名 YAML 模板 |
| `ack-perf/secret.example.env` | ACK 压测 Secret/环境变量模板 |
| `ack-perf/ekuiper.env` | ACK 压测 eKuiper 环境变量模板 |
| `ack-perf/configmap/*.yaml` | ACK 压测固定文件名 ConfigMap 模板 |
| `ack-prod/secret.example.env` | ACK 生产 Secret/环境变量模板 |
| `ack-prod/ekuiper.env` | ACK 生产 eKuiper 环境变量模板 |
| `ack-prod/configmap/*.yaml` | ACK 生产固定文件名 ConfigMap 模板 |


这些模板不是完整 Helm chart，仅表达目标配置形态。落地时应由 Helm template 或 Compose 挂载把 `common.yaml` 和服务 YAML 成对放进每个容器的 `/app/etc`，而不是把环境名塞进 YAML 文件名。

## 9. Secret 分层
| 类型 | 本地 | 压测 | 生产 |
| --- | --- | --- | --- |
| DB 密码 | `.env` 开发值 | K8s Secret | K8s Secret + KMS |
| Redis 密码 | 可为空 | K8s Secret | K8s Secret + KMS |
| JWT/Rej secret | `.env` 开发值 | K8s Secret | K8s Secret，定期轮换 |
| OSS/SMS/Map AK | 尽量禁用或开发 AK | 测试 AK | 最小权限生产 AK |
| EMQX/NATS 凭据 | 开发账号 | 测试账号 | 独立生产账号 |
| AuthWhite | 本地宽松 | 收敛到测试服务账号 | 只保留必要服务账号 |


绝对不要把现有 `.env` 中的真实公网 RDS、Redis、OSS AK 复制到模板文件。

## 10. 发布与晋级流程
配置从本地到生产的晋级规则：

1. 本地验证：Compose 能启动，API 冒烟、MQTT 冒烟、TDengine 写入通过。
2. 压测验证：ACK `auxsol-test` 使用 `k8s://` RPC，S0/S1/S10 场景通过。
3. 压测冻结：记录 `values.yaml`、ConfigMap checksum、Secret version、镜像 tag。
4. 生产发布：只允许从已通过压测的配置版本复制差异，生产只改命名空间、域名、资源规格、Secret 引用和生产依赖地址。
5. 回滚：保留上一版 ConfigMap/Secret version 和 Helm revision。

## 11. 验收清单
| 环境 | 必须验证 |
| --- | --- |
| 本地 | `docker compose config` 通过；API 端口可访问；eKuiper MQTT source 指向 EMQX；无真实 Secret |
| 压测 | `helm template` 通过；ConfigMap 无明文密码；`k8s://` RPC 调用正常；S10 服务发现场景通过 |
| 生产 | 不存在 `Mode: direct`；Secret 不在 values 明文；镜像 tag 不可变；回滚方案已记录 |
