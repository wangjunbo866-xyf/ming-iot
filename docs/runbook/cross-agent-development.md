# 跨 Agent 通用接入

新成员、新 clone 和新 coding agent 从本页接入。规则来源是 [AGENTS.md](../../AGENTS.md)、[团队约定](team-development.md)和模块当前规格；本页不复制业务规则。当前为局部试跑，不宣称全团队采用或所有宿主自动加载。

<a id="task-mode"></a>
## 日常任务怎样接入

从现有任务/Issue/PR 确认目标、修改范围、责任及验收，按任务进入相关 Feature 或 runbook。需要分工时，在同一任务中明确各自版本、范围和交付物；接手者据此执行和回报。工具选择按[公共约定与个人方法](team-development.md#shared-workflow)处理。

## 让当前 Agent 找到同一套规则

宿主自动读取根 AGENTS.md 时，以实际读取结果为准；首次使用仍核对下面的接手输出。宿主未自动读取时，直接给它这段任务前言：

> 从仓库根 AGENTS.md 开始，按本次任务选择入口，涉及业务时先找到 Feature 当前 spec，操作任务则进入对应 runbook；仅在需要原因、变更或工具操作时继续读取相应章节。说明实际规则入口、修改范围和验证。规格维护任务按仓内 ming-specs/SKILL.md 的任务表选择读取与写回位置；操作知识与入口维护按仓内 ming-runbook/SKILL.md 执行；无需安装全局 Skill。业务含义未确认时提出具体问题，先推进不依赖回答的工作。

支持原生 Skill 的宿主可按任务显式选择 [ming-specs](../../.agents/skills/ming-specs/SKILL.md) 或 [ming-runbook](../../.agents/skills/ming-runbook/SKILL.md)；其他宿主把对应文件当 Markdown 操作说明读取。相对链接按文件目录解析。CLI 参数、发现路径和权限模式以本机帮助及实际运行结果为准。工具启动或列表有名称不能单独证明接入成功。若无界面模式要求权限确认却没有确认客户端，保留失败并接入正常交互客户端，逐项核对任务授权；不把切换为全量放行模式当默认修复。

若需要宿主专用规则文件，只放指向本入口的短导航，不复制业务和流程正文。本轮验证通用读取路径，不自动生成各种 Agent 配置、不安装 Hook、不修改全局设置。

## 开工到交付

1. **确认版本和环境。** 检查分支、Head、已有改动，按[开发入口](daily-development.md)准备依赖。普通任务不需要维护者的私有配置、聊天历史或全局 Skill。先在该 Agent 实际执行命令的终端核验 Go、Python、Git 等依赖；另一个终端可用不代表它的 PATH 相同。
2. **找到当前规则。** 从[业务地图](../specs/README.md)进入模块，读当前 spec 和相关代码/测试，仅按需追溯 Patch。首次回报规则路径/版本、改变与不变项、委托边界及验证方案。源码现状不自动成为批准要求。
3. **选择最小记录。** 按[小修改步骤](team-development.md#small-changes)判断规则是否变化。规则不变时复用原任务/PR 的条款、范围、理由及回归；仅在确有说明缺口时改 spec。规则变化须真实确认及对应 Patch，不能伪装成轻量修复。
4. **实施并验证。** 优先复用用户指定的现有候选，在隔离分支/工作树只改获准范围，按需同步规格和测试。工具缺失、权限拒绝、未运行和失败分别留证；可选工具不可用时使用仓内文档和通用命令继续，必需工具缺失时报告具体缺口。
5. **固定候选并检查完整差异。** 验证后本地提交，按[PR 检查说明](../../.agents/skills/ming-specs/references/pr-check.md)生成声明，显式传入实际目标分支 tip、候选 Head 和声明文件。临时声明/输出留在仓外或忽略目录。小任务可以多次提交，基线仍为本次实际目标分支，不是最后一个提交的父提交。
6. **交付并复审。** 提供模块入口、真实 base/head、检查结果及未验证边界。独立 Reviewer 评审同一候选；提交、推送和合并按[动作边界](team-development.md#delivery-boundaries)核对授权。Skill 使用、结构通过、代码测试和业务验收分别记录。

人和任意具备命令执行能力的 Agent 均可调用 make knowledge-check、make verify-pr 和 tooling/specs_pr.py。前两者不替代带声明的完整 PR 差异检查；本地事件回放不等于托管 CI。Hook 与远程强制规则均不是本页接入步骤。

## 接入验收

在无原聊天历史、无项目私有调度文件的完整 clone 中，用另一 coding agent 完成真实小修改。记录实际 Agent/CLI 身份、启动方式、输入、读取规则、修改文件、规格判断、检查命令和结果，并独立核对 diff。保留一次缺声明等结构反例及修正后结果，不人为制造业务错误。

区分文件已获得、Agent 已读取执行、检查发现结构遗漏和语义评审通过。本次试跑不证明所有 Agent、全新账号认证、所有操作系统或长期收益。共享编译缓存与账号配置如实记录；准备成本与日常需求成本分开。
