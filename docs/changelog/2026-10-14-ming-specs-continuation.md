## 已落地的最小机制

1. Change 开头维护唯一的 `status` 与 `revision`。v2 `check.json` 不再复制它们；v1 保留结构检查兼容，但不能生成有版本保证的实施交接包。
2. 交出者对明确的基线和已提交候选生成 JSON 附件，包含候选 commit/tree、任务、模块、状态、revision、认领范围、四份输入与差异的指纹。
3. 接收者核对收到的附件；字段失配、已跟踪工作区/索引/HEAD 偏离指定候选时退回。未跟踪文件另列，不冒充已检查。
4. 普通 Patch 只维护一个决定正文、机器认领投影和必要的接收回执。交接说明引用正文、附件及下一步；不再手填第二份状态表。阶段试验才单列本类成本报告。

具体使用见[团队约定](../runbook/team-development.md)、[Skill](../../.agents/skills/ming-specs/SKILL.md)与[检查说明](../../.agents/skills/ming-specs/references/pilot-regressions.md)。附件是固定证据，不是另一份业务权威；它不认证交出者身份、授权、远端最新状态、测试或评审附件真实性。
