## 演练方法

接收者不继承原聊天，只获得干净 clone 的位置、接手目标、只读范围和证据输出位置。未向它提供业务规则答案或评分清单。它从根入口自行定位当前规格、代码、测试、版本、责任和未知项；只按需追溯历史，无需交接包。

clone 使用 `--no-local --single-branch`，Head 为上述 S2 提交，tree 为 `8ad840d9c553b07063183cc85ac9819f2249f2f0`。初始状态干净，不含维护者的 `.loopx`、`.local`、`.codex`，没有 Git 对象替代目录。接收任务不运行 LoopX、不读取旧仓或父任务材料、不连接真实推送通道；Goal 写回由已经准入的主 Agent 负责。

这是本机新检出、无聊天历史的 AI 演练，不是全新操作系统或权限隔离环境。允许使用已安装工具与模块缓存；依赖缓存和测试执行条件在私有回执中记录。导航计时、命令计时和报告整理时间分别记录，不把报告制作算作日常必填文书。

## 发现与修正

接收者通过当前导航找到 current-v1，并从代码核实名称、按钮动作及正文兼容规则；它指出主规格缺少调用层的明确说明。原文描述 `PrependRuleSceneTriggerLine` 处理 manual 的方式，但实际 `SendNotifyMsg` 的 ruleScene/manual 分支跳过前缀组装，`pushAppNotify` 又跳过 ruleScene 的前缀组装。读者可能因此误以为所有手动场景通知都会添加昵称行。

已在唯一 [主规格的 CALL-SITES](../specs/saas/notification-trigger/spec.md#call-sites) 记录适用源码的分支条件，并将原有两处表述限定为“直接调用辅助函数”。模块入口增加该节的按需指针。规则版本仍为 current-v1，业务代码和测试不变；新增调用说明是已观察到的现状，不代替新的业务取舍。原 R2 决定、absorbed Patch 与旧回执保持不变。

主 Agent 另核实 [来源索引](../index.yaml) 的团队约定、ming-specs 两条当前记录仍为 0.4.0-draft，而正文已是 0.5.0-draft。本次仅修正这两条当前版本，不改写 S1 等历史报告中的原版本。

现有主规格足以容纳该局部调用关系，未新增架构正文或第二份业务说明。团队约定与 ming-specs 已要求从当前入口接手、发现缺口后回补唯一正文，本次沿用这些步骤，无需新增 Skill、Hook、模板或强制交接产物。
