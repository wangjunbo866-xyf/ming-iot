## 还缺什么

- **服务端合并限制：** 2026-10-16 读取 GitHub main 分支，`protected=false`；仓库规则集为空。工作流已运行不等于失败时无法合并。本轮只读核验，不修改权限。
- **人的责任：** [通知模块](../specs/saas/notification-trigger/README.md) 与 [API 校验模块](../specs/engineering/api-contract/README.md) 都明确长期负责人未分配。用户对一次业务决定的确认、AI 的任务认领和自动检查均不能代替长期归属。
- **连续演进与维护成本：** 尚无新的真实业务调整验证主规格在再次修改后仍然完整。S3 是一次 AI 演练，有路径隔离限制，无对照组，不是真人验收或长期效率提升证据。
- **覆盖范围：** 当前 PR 映射只覆盖两个试点模块。设备接入、遥测、OTA、租户权限等知识仍需随实际任务核实；现有产品文档和历史资料不是空白，也不能整体自动升级为现行规格。
- **真实运行：** 无外部服务 CI 不能证明数据库、Kafka、通知渠道、真实设备或生产环境正确；只有实际变更需要时再选择相关集成验证，不把每次文档修改升级成完整发布测试。
