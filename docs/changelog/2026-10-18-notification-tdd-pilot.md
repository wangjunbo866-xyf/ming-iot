## 范围与认领

- Feature：`saas.notification-trigger`，依据 [current-v1 / BODY-COMPATIBILITY](../specs/saas/notification-trigger/spec.md#body-compatibility) 与 BOUNDARY。任务级委托、AI 细化；用户授权选真实小改动并试跑，不伪造逐条人工签字。长期模块负责人仍未分配。
- 基线：`05e7bca243550cb291fff58fb3e38aba03eb367f`；沿用原候选分支，保留此前全部改动。实施为主 Agent，审计为未参与实现的独立 AI 评审者。
- 写范围：通知 `triggerUserParams.go` 及同名测试；模块规格/入口、流程及其索引、总纲状态和本记录。没有前端、接口、存储、消息通道或共享 Schema 变化，无需跨模块业务确认。
- 分类：`no_behavior_change` 指恢复“完整首行不重复添加”的约定，错误输出会变化。规则无新增业务取舍，不建立 raw 或 Patch；文档补明 LF/CRLF 边界并标注本地候选。
- 本轮无同条款并行写入；审计者只读候选。先不推送、不新建 worktree 或强制门禁，旧环境、数据、旧仓和私有备份保留。

## 第二轮：个人计划不入仓的接续试跑

本轮用户授权使用 Superpowers 从通知模块选一个真实小改动：个人 plan 留本地，按 TDD 实现，必要知识写回现有文档，再让不读取个人 plan 的独立 Agent 接续。基线为 `405a6739f31350632053d441809312010e739059`，复用现有候选工作树。此次不推送、不合并、不新增工作树；旧环境、数据与历史回执保留。

### 范围、规则与认领

Feature 仍为 `saas.notification-trigger`，依据 current-v1 / BODY-COMPATIBILITY 的“仅清理首尾完整旧账号行，不清理正文中间同文行”。当正文恰为三个 LF 分隔的旧账号行时，既有流程在移除首尾后，又把剩余中间行作为“唯一整行”清空；这是违反既定规则的实现缺陷，不是新增需求或已知生产事故。本轮按 `no_behavior_change` 恢复规则，不新增 raw 或 Patch。

实施由主 Agent 协调独立实施 Agent，评审由未参与实现、无父聊天历史的独立 Agent 承担；需求依据为本次用户委托与现行规格，人的长期模块负责人仍未分配。代码写入限既有格式化实现与测试；文档限当前 spec、Feature README、本记录及索引。名称优先级、发送层条件、接口、Schema、数据库、外部推送均不改；无同条款并行代码写入。

### 方法与证据边界

使用本机 Superpowers 6.3.0 的 writing-plans、test-driven-development 与 subagent-driven-development；Skill 副本版本及内容摘要留原任务附件。个人计划在仓外，未修改全局安装，也不随候选提交。按用户要求，接续 Agent 的输入使用当前团队规格与 Git 差异，省去个人计划、计划提取副本、实施报告和父聊天；不把这些个人材料改名后塞入团队文档。

当前主规格补充了原正文的单行判断边界与三行例子，三个实际格式化入口的目标回归为 `TestManualTriggerBodyPreservesInteriorLegacyLine`。本例是纯文本兼容修复，无需启动旧环境；其包级验证不能证明真实推送或生产部署。

### 实际结果与接续验收

基线通知包通过。2026-10-18 13:58:27–13:58:30 UTC 的红灯运行退出 1，耗时 3.447 秒：18 个叶子用例中，三个实际入口的“三个 LF 行”和“CRLF 后接 LF”共 6 个断言因中间正文被清空而失败，没有编译或环境错误。红灯实现与基线字节相同。13:59:14–13:59:18 UTC 的绿灯运行退出 0，耗时 4.292 秒，同一组 18 个用例全部通过；红绿测试 SHA-256 均为 `1f0437f34aeed62984ffb0a6bc2c63addfbc68c0fef1199dc39ff67463d4f756`。通知包回归及格式检查也通过。原始快照、命令、时间、退出码与日志保留在原任务受控附件，个人 plan 不能替代这些过程证据。

修复在移除首行前保留原始尾行判定，且仅按原始正文判断“唯一整行”。实施时发现，单纯前移唯一行判断会使“两行都是边界行”残留一行；因此调整实现而不降低测试预期。单行、两行、三行、四行及混合换行共同约束本次改动，没有循环清理正文。

接续结论限定为一次遵守读取范围的独立 AI 演练：不是操作系统权限隔离、真人接收、真实推送或生产部署验收。测试与审计依靠现有团队知识和代码，不要求接收者取得个人计划。
